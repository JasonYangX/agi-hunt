# AGI Hunt — 产品与技术实现方案

> AI 工具导航与开发者资源聚合站点。本文档覆盖信息架构、页面组成、交互定义、数据结构、响应式与视觉规范，以及可落地的技术路线。

---

## 1. 产品定位与边界

**一句话定义**：一个以「任务」而非「模型」为组织维度的 AI 工具索引，附带一套完全在浏览器本地运行的开发者小工具。

| 维度 | 决策 | 理由 |
| --- | --- | --- |
| 目标用户 | 开发者、产品经理、内容创作者 | 有明确任务，需要快速选型而非浏览资讯 |
| 核心价值 | 降低「找到一个可用工具」的时间成本 | 导航站的价值在筛选质量，不在条目数量 |
| 收录规模 | 首版 126 条，控制在 300 条以内 | 超过阈值后必须引入审核与去重流程 |
| 商业模式 | 首版无商业化 | 避免排序被竞价污染，先建立可信度 |
| 非目标 | 不做资讯流、不做社区、不做模型评测榜 | 这些需要持续运营，与「索引」定位冲突 |

**设计原则**

1. **检索优先于陈列**：首屏即搜索，分类是搜索的兜底路径。
2. **信息密度可控**：卡片只保留「名称 / 厂商 / 一句话 / 标签 / 定价 / 出口」，细节进抽屉。
3. **零干扰**：无弹窗、无登录墙、无第三方统计脚本。
4. **可维护**：内容与视图分离，替换数据源不影响渲染层。

## 2. 信息架构

```
AGI Hunt
├── 首页 = 工具库（/，默认路由）
│   ├── 页头（标题 + 说明 + 搜索 + 移动端筛选入口）
│   ├── 分类导航（14 个分类入口，可收录的链接）
│   ├── 筛选侧栏（分类 / 定价 / 标签）
│   ├── 结果区（排序、视图切换、计数、已选条件）
│   └── 工具详情（右侧抽屉，不离开列表上下文；独立 URL /tool/:id/）
├── 分类页（/category/:id/，14 个，各自可收录）
├── 开发者工具箱（/dev/）
│   ├── 导航（按 数据 / 编码 / 生成 / 文本 分组）
│   └── 工作区（12 个工具，单面板切换；独立 URL /dev/:id/）
├── 我的收藏（/favorites/，localStorage，本地态，noindex）
└── 关于（/about/，收录标准 / 数据说明 / 开发者工具 / 快捷键）
```

**分类体系（14 类）**

| 分类 | 说明 | 条目 |
| --- | --- | --- |
| 对话助手 chat | 通用对话、推理、多模态问答 | 21 |
| 写作润色 writing | 长文、改写、翻译、校对 | 7 |
| 图像生成 image | 文生图、图生图、放大 | 8 |
| 视频 video | 视频生成、数字人、剪辑与后期 | 9 |
| 音频 audio | 语音合成、音乐生成、转录与配音 | 6 |
| 编程开发 code | 补全、重构、应用生成 | 11 |
| Agent 与自动化 agent | 编排、工作流、浏览器代理 | 8 |
| Agent 技能 skill | SKILL.md 技能库、市场与开放标准 | 6 |
| MCP 服务 mcp | Model Context Protocol 服务器与目录 | 10 |
| AI 学习 learn | 课程、教材与动手实训平台 | 10 |
| 搜索与研究 search | 联网检索、文献、知识库 | 8 |
| 设计创意 design | UI、排版、抠图、品牌 | 6 |
| 效率办公 productivity | 文档、演示、会议 | 7 |
| 模型与 API model | 托管、推理、本地运行 | 9 |

分类之间允许能力重叠，但每条工具只归入**最常用的任务场景**，避免同一工具在多个分类重复出现造成检索噪音。

音频与视频按产出形态拆分：`video` 覆盖视频生成、数字人与剪辑后期，`audio` 覆盖语音合成、音乐生成、转录与配音。跨界条目（如 Descript 的播客剪辑）按主用途归入视频，避免两个分类重复收录。

## 3. 页面组成与交互定义

### 3.1 默认入口与导航

工具库即站点首页，页面主体与筛选能力完全复用工具库，不再单独维护营销落地页。

| 场景 | 规则 |
| --- | --- |
| 根路径 `/` | 直接渲染工具库首页，`/tools` 不再是独立页面 |
| 分类 `/category/:id/` | 渲染该分类的工具列表，H1 为「{分类名} AI 工具」 |
| 旧 hash 地址 `#/tool/:id` 等 | 启动时识别并用 `location.replace` 跳到目录化地址，保证历史外链与书签可用 |
| 未知路径 | 渲染站内 404 视图，不做静默重定向（避免软 404）；静态托管返回 `404.html` |
| 品牌 Logo / 菜单「首页」 | 均指向 `/` |
| 菜单高亮 | 首页、分类页、工具详情统一高亮「首页」 |
| 命名口径 | 导航项称「首页」，页面 H1 为「AI 工具库」，指向同一路由 |

### 3.2 首页（工具库）

| 功能 | 交互方式 | 状态与反馈 |
| --- | --- | --- |
| 页头 | 标题、说明、搜索框、移动端筛选入口 | 桌面端搜索常驻；移动端搜索与「筛选」按钮同排 |
| 关键词搜索 | 页头输入框，输入后 120ms 防抖；`/` 聚焦 | 结果实时更新，URL 同步 `q` 参数，命中数实时显示 |
| 分类筛选 | 侧栏列表，单选，每项带分类图标与条目数 | 选中项反色；与关键词、定价、标签为「与」关系 |
| 定价筛选 | 复选式但互斥（不限 / 免费 / 免费增值 / 付费） | 选中显示勾选框 |
| 标签筛选 | 11 个高频标签，多选 | 多标签为「与」关系（结果更窄），选中态为深色胶囊 |
| 排序 | 下拉：推荐（精选优先 + 收录时间）/ 最近收录 / 名称 A–Z | 立即重排 |
| 视图切换 | 卡片 / 列表 | 仅切换容器 class，不重新请求 |
| 已选条件 | 结果区上方胶囊，可单个移除，附「清空条件」 | 无结果时展示空状态与一键重置 |
| 工具详情 | 点卡片从右侧滑出抽屉（480px） | 焦点移入抽屉；`Esc` / 点遮罩 / 关闭按钮退出；Tab 焦点锁定 |
| 收藏 | 卡片右上角星标，详情内也可操作 | 即时写入 localStorage，Toast 提示；收藏页同步刷新 |
| 移动端筛选 | 页头「筛选」按钮唤起底部抽屉 | 遮罩点击关闭，选择后保持展开以便多选 |

**URL 状态契约**（可分享、可回退、每个状态一个真实地址）

```
/category/video/?q=视频&price=freemium&tags=中文,API&sort=newest
```

分类由**路径**表达（`/category/:id/`），关键词、定价、标签、排序由查询参数表达。筛选变化时使用 `history.replaceState` 写入，不产生历史堆栈；只有跨页面跳转（分类切换、打开详情）才产生新的历史记录。查询参数页不参与索引，统一 canonical 到所属分类页。

### 3.3 工具详情（抽屉）

内容顺序：图标与名称 → 厂商 → 一句话定位 → 完整描述 → 元信息（分类 / 定价 / 平台 / 收录时间）→ 主行动（访问官网）+ 收藏 → 标签 → 同类工具（同分类 4 条，可继续切换）。

- 打开时 `pushState` 到 `/tool/{id}/`，关闭时 `history.back()`，浏览器返回键行为一致；
- 直接访问 `/tool/{id}/` 会先渲染工具库作为背景，再打开抽屉；
- 抽屉打开时锁定 body 滚动。

### 3.4 开发者工具箱

左侧为分组导航，右侧为单面板工作区。切换工具不刷新页面，仅替换面板内容（路由 `/dev/{id}/`）。

| 工具 | 输入 | 输出 / 反馈 |
| --- | --- | --- |
| JSON 格式化 | 文本域 | 实时校验，错误定位到行列；支持缩进 2/4/Tab、压缩、键排序、复制、节点数与深度统计 |
| Base64 | 文本域，双向切换 | UTF-8 安全；URL-safe 选项；解码失败给出明确提示 |
| URL 编解码 | 文本域 | encodeURIComponent / decodeURIComponent；自动拆解 query 参数为表格 |
| 哈希计算 | 文本 + 算法选择 | SHA-1/256/384/512，输出 HEX 与 Base64，防抖 120ms |
| JWT 解析 | 文本域 | 解出 Header / Payload 并格式化；渲染 iss/sub/exp 等声明，标注是否过期；明示不校验签名 |
| UUID 生成 | 数量 1–100 | 批量生成 v4，可选大写、去连字符，一键复制 |
| 时间戳转换 | 数字或日期字符串 | 顶部实时时钟；秒/毫秒自动识别；输出本地、ISO、UTC、相对时间 |
| 颜色转换 | HEX / RGB / HSL | 色块预览、三种格式互转、9 级明度阶梯（点击复制） |
| 正则测试 | 表达式 + flags + 文本 | 匹配高亮、数量、分组与 index；非法表达式即时报错 |
| 文本统计 | 文本域 | 字符、汉字、西文词、行、段落、预估 Token、阅读时长 |
| Markdown 预览 | 文本域 | 120ms 防抖渲染；支持标题、列表、引用、代码块、链接、强调 |
| 文本对比 | 双文本域 | 逐行 LCS 差异，绿增红删，统计增删行数 |

**共同约束**：所有计算在浏览器内完成，无网络请求；输入内容不持久化（刷新即清空）；敏感场景可断网使用。

### 3.5 全局命令面板

`⌘K` / `Ctrl+K` 唤起。默认展示 5 个精选工具、4 个开发工具；输入后跨工具名、厂商、标签、分类、工具描述检索。`↑↓` 选择、`Enter` 打开、`Esc` 关闭；结果按「工具 / 开发工具 / 分类」分组。

### 3.6 收藏页

读取 localStorage，展示已收藏工具卡片；为空时给出引导与入口。收藏不关联账号、不上传。

## 4. 数据结构设计

### 4.1 实体关系

```
Category 1 ── n Tool          （每条工具属于一个主分类）
Tool     n ── n Tag           （以字符串数组内嵌，首版不单独建表）
DevTool                       （独立元数据 + 前端渲染函数）
Favorite                      （本地集合，仅存 toolId）
```

### 4.2 类型定义

```ts
type Pricing = 'free' | 'freemium' | 'paid';
type Lang = 'zh' | 'en' | 'multi';
type Platform = 'web' | 'mac' | 'win' | 'ios' | 'android' | 'api' | 'self';

interface Category {
  id: string;          // 稳定标识，用于 URL 与关联
  name: string;        // 展示名
  hue: number;         // 0–360，用于图标底色与卡片强调色
  desc: string;        // 一句话说明
  icon: string;        // 内联 SVG path，避免图标字体依赖
}

interface Tool {
  id: string;          // 唯一 slug，兼作详情 URL
  name: string;
  vendor: string;
  cat: string;         // → Category.id
  tagline: string;     // 一句话定位（≤ 20 字）
  desc: string;        // 60–90 字，说明能力边界
  url: string;         // 官网/产品入口，https
  logoHost?: string;   // 可选：图标来源域名，默认取 url 的 host（如仓库页指向品牌官网）
  tags: string[];      // 2–4 个，受控词表
  pricing: Pricing;
  lang: Lang;
  platforms: Platform[];
  featured: boolean;   // 编辑精选，参与默认排序
  added: string;       // YYYY-MM-DD，用于「最近收录」
}

interface DevTool {
  id: string;          // 与渲染函数注册表 key 一致
  name: string;
  badge: string;       // 2–3 字符的等宽标识
  group: '数据' | '编码' | '生成' | '文本';
  desc: string;
}
```

### 4.3 示例记录

```json
{
  "id": "comfyui",
  "name": "ComfyUI",
  "vendor": "开源社区",
  "cat": "image",
  "tagline": "节点式生成管线的事实标准",
  "desc": "基于节点图的本地生成工作台，支持 SD、FLUX 等模型与 ControlNet、LoRA 组合，可导出 API 工作流。",
  "url": "https://www.comfy.org",
  "tags": ["开源", "本地部署", "工作流", "节点"],
  "pricing": "free",
  "lang": "en",
  "platforms": ["mac", "win", "self"],
  "featured": true,
  "added": "2026-08-02"
}
```

### 4.4 约束与索引

- `id` 全局唯一且不可变（变更会造成外链与收藏失效）；改名时保留 redirect 映射。
- `tags` 使用受控词表，避免「AI 对话 / 聊天 / Chat」同义分裂；首版词表约 60 个。
- 默认排序权重：`featured` 优先，其次 `added` 倒序；搜索命中时改为相关度优先（名称 10 / 厂商 6 / 标签 5 / 定位 4 / 分类 3 / 描述 2，多词累加，任一词不命中即淘汰）。
- 收藏仅存 `id[]`，读取时与工具表 join，工具下线自动失效（渲染时过滤）。

### 4.5 数据演进

首版数据以 `assets/js/data.js` 常量形式内联，换取零请求与离线可用。条目超过约 500 条后按以下路径演进：

1. 抽出 `tools.json`，由构建期注入，减小主包；
2. 迁移至 Postgres（`tools` / `categories` / `tags` / `tool_tags`），管理后台负责增删改；
3. 检索切到 Meilisearch 或 pg_trgm，前端只保留查询与渲染；
4. 增加 `status`（active / deprecated）、`verified_at`（最近核验时间）字段，支撑过期治理。

## 5. 响应式布局

### 5.1 断点

| 断点 | 范围 | 布局变化 |
| --- | --- | --- |
| Desktop | ≥ 1081px | 12 列栅格；首页（工具库）216px 侧栏 + 结果区；工具箱 232px 导航 + 面板 |
| Laptop | 901–1080px | 侧栏收窄至 190/200px；页脚三列 |
| Tablet | 721–900px | 顶部导航折叠为汉堡菜单；筛选变为底部抽屉；工具箱导航变为横向滚动条；列表视图隐藏描述 |
| Mobile | ≤ 720px | 单列卡片；抽屉全屏；统计块 2 列；页脚 2 列 |

### 5.2 容器与栅格

- 内容最大宽度 1240px，左右留白 24px（移动端 16px）。
- 卡片栅格使用 `repeat(auto-fill, minmax(292px, 1fr))`，不写死列数，容器变化时自然回流。
- 间距采用 4px 基准：8 / 12 / 16 / 24 / 32 / 44 / 64。

### 5.3 触控与可访问性

- 所有可点区域 ≥ 36×36px；卡片整体可点，星标与链接独立热区并阻止冒泡。
- 抽屉打开时锁定背景滚动、焦点移入、Tab 循环、`Esc` 关闭、关闭后焦点归还。
- 交互元素提供 `aria-label` / `aria-pressed` / `aria-current`；抽屉为 `role="dialog" aria-modal="true"`。
- 正文对比度 ≥ 4.5:1；焦点环使用 2px 主题色 outline，不依赖颜色单独传递状态。
- 尊重 `prefers-reduced-motion`，关闭全部位移动画。

## 6. 视觉风格

### 6.1 基调

「纸感 + 墨色 + 单一强调色」。背景为暖白（#F6F6F2），卡片纯白，文字近黑（#14161B），强调色为靛蓝（#3D4FE0）。分类色只用于分类图标与工具标识的兜底色块，不参与大面积填充，避免导航站常见的花哨感。

### 6.2 令牌

| 类别 | 值 |
| --- | --- |
| 背景 / 卡片 | `#F6F6F2` / `#FFFFFF` |
| 次级面 | `#F1F1EC`（标签底、hover） |
| 文字三级 | `#14161B` / `#4B505B` / `#868C99` |
| 描边 | `#E3E3DC`，强描边 `#D1D1C8` |
| 强调 | `#3D4FE0`，浅底 `#ECEEFE` |
| 语义 | 成功 `#1A7F5A`、警示 `#A8661A`、危险 `#C03A3A` |
| 圆角 | 8 / 12 / 18 / 26px |
| 阴影 | 三级，最大 `0 28px 70px -24px rgba(20,22,27,.28)` |
| 字体 | 系统栈：SF Pro / PingFang SC / Segoe UI / Noto Sans SC |
| 等宽 | SF Mono / JetBrains Mono / Menlo，用于工具标识与数据 |
| 字号 | 正文 15px，卡片 13px，辅助 11–12px，页头 H1 clamp(26→34px) |

### 6.3 排版与细节

- 标题字重 650–700，字距 `-0.03em`，中文大字号下收紧以避免松散。
- 卡片标题 15px / 600，描述 13px / 1.65，最多两行截断。
- 图标统一 1.6px 描边、圆角端点，尺寸 16–19px。
- 工具标识优先读取站点自身的 apple-touch-icon / favicon；不可用时以「首字 + 分类色相偏移」生成兜底色块，避免空白占位。
- 动效时长 160–320ms，缓动 `cubic-bezier(.22,.61,.36,1)`；卡片 hover 位移不超过 3px。
- 深色模式为完整令牌覆盖（背景 #0E0F12、卡片 #16181D、强调 #8494FF），非简单反色；默认跟随用户手动选择，首次为浅色。

## 7. 技术实现方案

### 7.1 当前实现（已落地）

```
agi-hunt/
├── index.html              # 应用外壳：图标精灵、静态页头页脚、默认元信息槽位
├── build.mjs               # 构建期预渲染：生成 dist/ 静态页、robots.txt、sitemap.xml
├── package.json            # 仅两个脚本：build / preview，无依赖
├── assets/
│   ├── css/styles.css      # 设计令牌 + 组件 + 响应式（单文件分节）
│   └── js/
│       ├── data.js         # 分类 / 工具 / 开发工具元数据
│       ├── seo.js          # 每条 URL 的 title / description / canonical（构建期与运行期共用）
│       ├── devtools.js     # 12 个工具的实现与挂载
│       └── app.js          # 路由、检索、筛选、抽屉、命令面板、主题
├── .github/workflows/pages.yml   # CI：node build.mjs → 部署 dist
└── docs/architecture.md    # 本文档
```

- **构建期预渲染、运行期零依赖**：`node build.mjs` 把 `index.html` 按路由复制成一份份静态页（含完整正文、独立元信息与 JSON-LD），浏览器端仍由原生 JS 接管交互。源文件不再支持 `file://` 双击打开，本地预览用 `npm run preview`。
- **路由**：History API，路径与静态目录一一对应——首页 `/`、分类 `/category/:id/`、工具 `/tool/:id/`、工具箱 `/dev/` 与 `/dev/:id/`、`/about/`、`/favorites/`。旧版 `#/tool/:id` 外链在启动时被重定向到对应目录。站内 `<a href>` 均为真实路径，点击由事件委托接管，保留中键新开与抓取器可读性。
- **渲染**：模板字符串 + 事件委托。列表重渲染只替换 `#results-area`，不重建侧栏，避免输入焦点丢失。脚本置于 body 末尾且同步执行，预渲染 HTML 会在首帧前被同构视图替换，不产生可见闪烁。
- **图标**：优先读取各站点自身的 `apple-touch-icon.png`，失败后依次尝试 `favicon.svg`、`favicon.ico`，全部不可用时回退为首字色块（按分类色相生成）。不使用第三方图标服务，图片请求带 `referrerpolicy="no-referrer"` 且懒加载。静态预渲染页只输出首字色块，不发起跨域图标请求。
- **状态**：筛选状态存于内存并镜像到 URL；收藏与主题存于 localStorage；无全局状态库。
- **检索**：前端线性打分，126 条量级下耗时 < 1ms，无需索引结构。

**为什么不用框架**：首版是内容型站点，交互集中在筛选与抽屉。引入 React/Vue 会带来 40KB+ 运行时与构建链，收益不足以抵消首屏与维护成本。当前四个脚本合计约 160KB（未压缩，gzip 后约 42KB），其中数据文件占一半以上；CSS 约 38KB（未压缩）。

### 7.2 规模化路线

| 阶段 | 触发条件 | 方案 |
| --- | --- | --- |
| A. 静态原生（当前） | < 500 条、单人维护 | 继续使用，补充 `tools.json` 构建期注入 |
| B. Astro + Content Collections | 500–3000 条、需要更强的内容编排 | 在现有预渲染之上引入组件化与内容集合，检索与筛选作为 island hydrate |
| C. Next.js + Postgres + Meilisearch | 需要账号、UGC、后台审核 | App Router + ISR；检索交给 Meilisearch；收藏上云 |
| D. 多端 | 需要小程序 / App | 抽出 API 层，Web 与小程序共用数据契约 |

迁移时保持不变的契约：`Tool` 字段、URL 参数命名、分类 id、搜索权重。这四者是前后端的耦合面，先在文档中冻结。

### 7.3 部署

- 部署物是 `dist/`，由 GitHub Actions 在每次 push 时执行 `node build.mjs` 后上传，不再直接托管仓库根目录。
- 首次切换需在仓库 Settings → Pages 把 Source 改为「GitHub Actions」；`CNAME` 会被构建复制进 `dist/`，自定义域名与 HTTPS 不受影响。
- 也可部署于任意对象存储 / CDN（腾讯云 COS、Vercel、Cloudflare Pages），只需把 `dist/` 上传。
- 建议开启 Brotli、`Cache-Control: max-age=31536000` 作用于 `assets/*`（文件名带版本号时），HTML 使用 `no-cache`。
- 无需服务端运行时与数据库。

### 7.5 SEO 与可收录性

导航站的搜索流量来自「具体工具名 + 场景」的长尾查询，因此**每个条目必须是一个独立可收录的 URL**，而不是首页里的一个抽屉状态。

| 项目 | 实现 |
| --- | --- |
| URL 结构 | `/`、`/category/:id/`、`/tool/:id/`、`/dev/`、`/dev/:id/`、`/about/`、`/favorites/`（noindex）；目录化，静态托管无需 rewrite |
| 预渲染 | 每条 URL 由 `build.mjs` 输出带完整正文的 HTML：H1、工具描述、元信息表、标签、同类工具互链、分类导航 |
| 元信息 | 每页独立 `title` / `description` / `canonical`，规则集中在 `assets/js/seo.js`，构建期与客户端共用 |
| 结构化数据 | 首页 `WebSite` + `SearchAction`；分类页 `CollectionPage` + `ItemList`；工具页 `SoftwareApplication`（免费条目带 `Offer`）；全站 `BreadcrumbList` |
| 内链 | 首页与分类页输出全部工具链接；分类页互链；工具页链接所属分类与 6 条同类工具；页脚链接受众入口 |
| 重复内容 | 查询参数（`?q=` `?price=` `?tags=` `?sort=`）由 `replaceState` 写入，不进 sitemap，canonical 指向所属分类页 |
| 索引文件 | `robots.txt` 允许全站、屏蔽 `/favorites/`；`sitemap.xml` 覆盖除 404 与收藏页之外的全部 URL |
| 反软 404 | 未知路径返回 `404.html`（HTTP 404），客户端渲染站内 404 视图，不再静默重定向到首页 |

**已知限制**：工具页的客户端视图仍是「列表 + 抽屉」，只是把 H1 与导语换成当前工具，以与预渲染版本一致；真正的短板在内容——每条工具目前只有 60–90 字简介，属于薄内容，靠结构化数据与内链只能缓解，不能替代正文。下一步是给每条工具补 300–500 字的使用场景、免费额度边界与替代方案（P1）。
