# AGI Hunt 自然搜索增长方案

> 基线测量时间：2026-11-09 ｜ 对象：`www.agihunt.cn` 全站 177 个 HTML 页面
> 测量方式：本地 `dist/` 全量解析 + 线上响应头 + Git 提交历史。文中所有数字均为实测，不是估算。

---

## 0. 结论先说

1. **技术 SEO 不是瓶颈。** 预渲染、唯一 title/description、canonical、面包屑、JSON-LD、sitemap、robots、404 noindex 都已具备，这套底子在中文 AI 导航站里属于上游。
2. **流量为零的真实原因有三条，且都不在「技术」层面**：域名 6 天、单页正文中位 171 字、外部权威度为零。
3. **139 个工具页里有 133 个是「模板 + 两句话简介」**。这类页面不会被惩罚（因为量还小），但也几乎不可能排到任何有搜索量的词上。
4. **这个赛道的正面战场已经打完了。** ai-bot.cn 收录 5000+，6aiq 5000+，Futurepedia 8000+。用 139 条去打数量是必输的；用 139 条去打深度与特定人群，才有位置。
5. **未来 90 天的正确目标不是「涨流量」，是「让 30 个页面值得被排」+「建立 20 个能带来长尾的内容入口」**。流量是这两件事的结果，会滞后 2-3 个月出现。

## 2. 归因：流量为什么是零

### 2.1 域名与信任（不可压缩的时间成本）

新域名在 Google 侧需要数周到数月建立抓取与信任，在百度侧有明确的「新站考察期」，通常 1–3 个月才开始给稳定展现。这一条没有任何技术手段可以跳过，任何承诺「两周上首页」的方案都是在骗你。

### 2.2 页面价值密度（最大的可控问题）

工具页当前的结构是：`H1 + 一句话定位 + 两句话简介 + 6 个字段 + 标签 + 6 个同类链接`。

拿它去和 ai-bot.cn 上一个同样工具页比：对方有功能清单、价格表、优缺点、使用教程、用户评价。搜索引擎要判断「哪一页更能回答『ChatGPT 多少钱 / 和 Claude 有什么区别』」，答案不会是你。

**这不是「字数不够」，是「信息增量不够」。** 补到 800 字但全是套话，效果等于 0。

### 2.3 外部权威度（完全空白）

新域名、零外链、零品牌搜索。这个状态下，即使内容达标，排名天花板也被压在长尾。外链不是「可选项」，是这条赛道的入场券。

### 2.4 一个必须正视的行业事实

AI 导航站这个品类正在收缩：模型本身越来越会「直接给出工具建议」，纯目录的中间价值在被吃掉。2026 年下半年已有多个中文导航站停更或大幅缩减更新。

这不意味着不能做，意味着**不能再用「又多又全」的定位做**。你能活下来的位置只有两个：比大站更深，或者服务一个更窄的人群。

## 3. 战略：不打什么，打什么

### 3.1 明确放弃

| 放弃 | 理由 |
| --- | --- |
| 冲「AI 工具」「AI 导航」这类头部词 | 对手是 5000+ 条目的站群，DA 差距不是内容能补的 |
| 把条目从 139 扩到 1000+ | 在正文没补齐前扩容，等于批量制造低质页，会拉低整站质量评分 |
| 冲「ChatGPT 官网」这类纯品牌词 | 官方站 + 百科 + 大站占满首屏，投入产出比极低 |
| 批量 AI 生成 139 份简介 | 这是当前最容易被识别的低质模式，且会把已有的编辑可信度一起毁掉 |

### 3.2 三条可赢的战线

**战线 A：开发者工具的「不上传数据」定位（最快见效）**

你已经有 12 款纯前端工具，这是全站唯一具备**产品属性**而不是**索引属性**的资产。它们的搜索意图极强（「JSON 格式化」「JWT 解析」），而且有一个大站普遍不做的卖点：内容不出本机、无广告、无登录、断网可用。

打法不是去和 bejson、tool.lu 拼关键词覆盖，而是把「隐私」做成品牌标签：
- 每页加「这个工具在本地算什么、不算什么」的说明（已在做，需强化成固定模块）
- 做一篇《我们为什么坚持让工具在浏览器里跑》——这是能被引用、能被转载的立场文章
- 目标不是这些词的第一名，是让「不上传数据的在线工具」这串词指向你

**战线 B：本地部署与算力实证（最可能拿到外链）**

这不是拍脑袋的方向，是**你本人具备真实经验**的方向：12 GB 显存能跑什么、跑 FLUX 要多久、量化到什么程度会崩。这类内容满足 E-E-A-T 里的 Experience，而大站几乎没有（他们不实测，只转录）。

可做的资产：
- 《12 GB 显存能跑哪些模型：实测清单》——按量化等级列，带速度
- 《RTX 4070 Ti 跑 SDXL / FLUX / 视频模型的真实耗时》
- 《本地 LLM 显存对照表：7B/14B/32B 在什么配置下可用》

这类页面天生适合被论坛、公众号、GitHub README 引用，外链成本最低。

**战线 C：对比与选型（商业意图 + AI 搜索引用）**

「Cursor 和 Copilot 怎么选」「Kimi 和 NotebookLM 差别」这类对比型查询，转化意图强，而且 AI 概览倾向引用结构清晰、有明确结论的页面。你现在工具页里的「和同类怎么选」小节就是为这个准备的，需要扩成独立文章。

### 3.3 关键词分层

| 层级 | 示例 | 竞争 | 你的胜算 | 优先级 |
| --- | --- | --- | --- | --- |
| 品牌 + 意图 | 「Cursor 价格」「Claude 免费额度」 | 高 | 中（靠深度 + 结构化） | P1 |
| 品类 | 「AI 编程工具」「MCP 服务器」 | 高 | 低（分类页可守） | P2 |
| 场景长尾 | 「12G 显存能跑什么模型」「本地部署 RAG 要多少显存」 | 低 | **高** | P0 |
| 工具词 | 「JSON 格式化」「JWT 解析」 | 极高 | 中（靠隐私定位切细分） | P1 |
| 新兴生态 | 「DSH 插件」「Agent Skills 怎么用」 | **极低** | **最高** | P0 |

> 搜索量请用百度指数 / 5118 / Google Keyword Planner / GSC 实际数据核对后再定优先级。上表是竞争结构判断，不是搜索量数据——我不会在没拿到数据的情况下给你编数字。

**一个被低估的机会**：DSH（DeepSeek Harness）你有 13 个页面，这是全网几乎没有竞争对手的赛道。生态早期、搜索量不大，但「小池塘里的第一」比「大池塘里的第五百」有价值得多——它能带来第一批真实用户和外链。

## 5. 工具页内容模板

已在 `content/tools.js` 落地，字段缺省则该段不渲染。

| 段落 | 回答的问题 | 字数 | 注意 |
| --- | --- | --- | --- |
| `what` 是做什么的 | 它到底解决什么问题 | 120–200 | 讲机制，不讲形容词 |
| `fit` 适合 | 谁该用它 | 3 条 | 具体到任务，不写「适合所有人」 |
| `notFit` 什么情况下别选 | 什么场景该走 | 2 条 | **这条最能建立可信度，别省** |
| `price` 定价与额度 | 免费够不够用 | 80–120 | 只写结构，不写易变的具体金额 |
| `start` 上手步骤 | 第一次怎么用 | 3 步 | 动词开头 |
| `diff` 和同类怎么选 | 为什么选它不选那个 | 100–150 | 点名对比，不拉踩 |
| `faq` 常见问题 | 真实搜索口吻的疑问 | 2–4 条 | 问题要像人搜的，不像产品 FAQ |

**反例**（这类内容写了等于没写）：

> ChatGPT 是一款强大的人工智能对话工具，能够帮助用户高效完成各类任务，是提升生产力的不二之选。

**正例**（现在页面上的写法）：

> 它真正的价值不是「什么都能问」，而是能把一件模糊的事推进到可执行——写出一版可以改的初稿、把一份看不懂的文档读成要点、把一个需求拆成能派活的步骤。

差别不在文采，在**是否包含只有用过的人才知道的信息**。

## 6. 两份值得做的内容资产

这两件事的共同点是：**别人引用你的成本很低，你更新的成本也可控**。这是新站拿外链最现实的路径。

### 6.1 AI 工具定价与额度数据库

- 结构：工具 / 免费档限制 / 个人档价格 / 团队档 / API 计价 / 最后核对日期
- 更新：每月一次，只改变化项
- 价值：被引用率高（价格是最常被问的问题），且天然产生 freshness 信号
- 风险：必须标注核对日期，写错价格会直接损伤可信度

### 6.2 本地部署显存与速度实测表

- 结构：模型 / 参数量 / 量化 / 显存占用 / 生成速度 / 可用性判断
- 硬件：以你手上的 RTX 4070 Ti 12 GB 为基准，标注清楚
- 价值：论坛、公众号、GitHub README 的高频引用对象
- 这是全站最难被复制的资产——因为需要真机器真跑

## 7. 收录与分发

### 7.1 收录（现在就该做）

| 平台 | 动作 | 状态 |
| --- | --- | --- |
| 百度搜索资源平台 | 站点验证 + sitemap 提交 + 普通收录 API | ✅ 已有验证与提交 |
| Google Search Console | 验证 + 提交 sitemap + 检查覆盖率 | ⏳ 待做 |
| Bing 站长工具 | 验证 + IndexNow | ✅ 密钥与脚本已就位，需部署后执行一次 |
| 头条搜索 / 神马 | 提交 sitemap | ⏳ 可选项 |

**境外托管的现实问题**：GitHub Pages 在境外，百度抓取频次会明显低于国内托管。如果百度是主战场，最终需要迁到国内对象存储 + CDN（需 ICP 备案，`.cn` 域名本身已要求实名）。如果主攻 Google / Bing，现状可接受。

### 7.2 外链（按性价比排序）

1. **GitHub**：把你的开发者工具和这份索引挂到相关 awesome 列表；在自建项目的 README 里放链接。这是新站最干净的第一批链接。
2. **开源社区**：DSH、MCP 相关项目提 issue / PR 时附带你的整理页（前提是真的有用，不要硬塞）。
3. **中文技术社区**：V2EX（分享创造节点）、掘金、少数派、知乎回答。原则是「先给完整答案，再放链接」，正文里贴链接会被删。
4. **被引用而非求链接**：数据资产做出来后，主动给引用过同类数据的公众号/博主发邮件说明更新。
5. **不要做**：买链接、链接农场、群发外链、友链交换页面。新站挨一次算法处理，恢复期比建设期还长。

### 7.3 分发（SEO 之外的加速器）

纯 SEO 在新站阶段是慢变量。同样一篇文章，发在掘金/知乎能带来当天的真实访问与自然外链，发在自己站上要等三个月。**先在外面发，再把站内页做成最完整的版本**，是更现实的顺序。

## 9. 度量：看什么，不看什么

**看**：

| 指标 | 工具 | 达标线（90 天） |
| --- | --- | --- |
| 收录率 | GSC 覆盖率 / 百度索引量 | > 80% |
| 展现量 | GSC 效果报告 | 周展现 > 3000 |
| 长尾词数 | GSC 有展现的 query 数 | > 300 |
| 平均排名（非品牌） | GSC | 进入 11–30 位为主 |
| 外链域名数 | 任意外链工具 | > 20 |
| 自然访问 | 任意统计 | 日均 50–150 UV |

**不看**：单日排名波动、Alexa 类排名、没有基线的「权重值」。

**时间预期（诚实版）**：

- 第 1 个月：收录爬升，展现量从 0 到几百，点击仍接近 0
- 第 2–3 个月：长尾词开始进 10–30 位，日均 UV 10–50
- 第 4–6 个月：若内容与外链都到位，日均 100–500；到不了说明有一个环节没做，不是「SEO 没用」
- 想稳定破千，需要 300+ 个有内容的页面和持续外链，属于 6–12 个月的事

## 10. 不要做的事

1. **不要为了「看起来内容丰富」把 139 条扩成 1000 条。** 在正文没补齐前扩容，是主动制造低质页。
2. **不要批量 AI 生成工具简介。** 你的差异化是「人来筛过」，一旦混入批量生成，这个差异就没了，且很难再讲清楚。
3. **不要买链接、不要做互链页。** 新站恢复期成本远高于建设期。
4. **不要在多个页面重复同一段介绍。** 这是导航站最常见的自我伤害：分类页、合集页、工具页三处同文。
5. **不要盯着排名做优化。** 盯「这个词的搜索者想解决什么」，排名是结果。

## 附录 B：内容补全怎么入手

### B.1 先做减法：不是 139 个页面都值得补

补内容最大的浪费，是把 600 字写在一个本来就不该独立存在的页面上。按搜索意图把 139 条分三类：

| 类型 | 数量 | 特征 | 处理方式 |
| --- | --- | --- | --- |
| **A 产品型核心** | 约 40 | 有品牌搜索、有定价页、用户会主动比价 | 逐页补深度内容，每页 600–900 字 |
| **B 产品型长尾** | 约 60 | 有明确用途但搜索量小 | 补到 400–500 字即可，不必堆 FAQ |
| **C 入口型** | 约 39 | 目录、仓库、课程、规范入口 | **不补独立页**，合并成 4 篇生态总览 |

C 类的构成：`skill` 6 个（全是技能库与市场）、`mcp` 里 7 个目录站、`dsh` 13 个（几乎全是插件市场与仓库）、`learn` 10 个（全是课程入口）。

**为什么合并比补写更划算**：这 39 个条目彼此高度同质，用户搜的是「MCP 服务器怎么选」而不是「smithery 是什么」。给每个写 600 字，等于制造 39 个互相竞争的薄页；写成 4 篇总览（Agent Skills / MCP 服务器 / DSH 插件 / AI 学习路线），每篇 2000–2500 字，既覆盖同样的长尾，又不稀释整站质量。

**时机**：现在做减法成本几乎为零。等页面被收录、有了外链和排名，再合并就要做 301 跳转、损失一部分信号。这是新站才有的一次性红利。

### B.2 单页生产流程（每页约 55 分钟）

| 步骤 | 时长 | 做什么 |
| --- | --- | --- |
| 1. 采事实 | 10 min | 打开官网，只抄 5 件事：定价档位、免费额度的限制、支持平台、最近一次重要更新、**一个明确的局限** |
| 2. 写 `notFit` 与 `diff` | 15 min | 先写这两段。它们决定这页有没有信息增量，也决定读者信不信你 |
| 3. 写 `what` 与 `start` | 15 min | 讲机制与步骤，不讲形容词 |
| 4. 写 `faq` | 10 min | 问题要用真实搜索口吻（「免费版够用吗」而不是「产品有哪些优势」） |
| 5. 校验 | 5 min | `node build.mjs` 看字数与标题宽度；通读一遍删掉「赋能 / 一站式 / 强大」 |

**采不到 5 个事实就不要动笔。** 没有事实支撑的段落，写出来一定是套话，而套话是负资产——它让读者（和搜索引擎）判断这页没有独家信息。

### B.3 写完自检三问

1. 这一页有没有一句「只有用过的人才知道」的话？
2. `notFit` 那段敢不敢明确说「这种情况别用它」？
3. 把这些内容删掉，读者会不会少知道一件事？

三问有一个是否，这页就不该发布。

### B.4 节奏与批次

- 每周 8 页，约 6–8 小时，5 周覆盖 A + B
- 每批写完提交一次 IndexNow，不要每天全量推
- 每批结束后看一次 GSC 展现量变化，模板有效再继续下一批
